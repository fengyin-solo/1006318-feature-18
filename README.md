# 城市地下综合管廊运行维护管理平台

面向管廊主体台账、入廊管线登记、廊内环境监测、通风排水消防、结构沉降与渗漏处置、巡检检修与隐患整改、入廊作业审批和运维值班的一体化城市地下综合管廊运行维护管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `urban-utility-tunnel:entries` 这一项，或调用 `resetModule(模块)`。

## 隐患整改管理：统一口径说明

隐患域（列表 / 运营概览 / 导出 CSV / 整改待办 / 应急演练评估清单）只有一份事实源，
即 localStorage 里的 `hazard` 数据；所有状态、逾期、待办标志由
`src/data/hazard-policy.ts` 的同一个纯函数 `deriveHazard` 派生，任何页面都不另算。

- **状态机**：待整改 → 整改中 →（提交验收）→ 已验收 / 退回重改。"已逾期"不是状态，
  而是派生标记：`未验收 且 整改期限 < 今天`，验收当天不算逾期；验收通过即清除，没有手工标逾期入口。
- **验收一次性落库**（`src/api/hazard-service.ts` 的 `acceptHazard`，同一事务）：
  验收日期、验收人员、验收结论、验收单号一次写入；通过则清逾期，退回则整改期限顺延并追加留痕。
- **重复验收幂等**：已验收隐患再次提交（含通过与退回）一律拒绝；演练清单按隐患编号 upsert，
  同一隐患重验只更新不新增；已评估的演练被重验时自动回到"待组织"并按验收日 +3 天重排。
- **整改期限推定规则**（存量回填与补录缺项共用）：依据《生产安全事故隐患排查治理暂行规定》
  （原国家安全监管总局令第16号：重大隐患须限期治理、一般隐患立即整改），结合管廊进舱作业排程
  实际取自然日历天：**重大 30 天 / 较大 15 天 / 一般 7 天 / 较低 3 天**，等级残缺按"一般"推定；
  退回顺延取 `max(旧期限, 今天) + 等级天数`，不允许往回拨。
- **存量回填**（迁移 v1，以发现日期为轴）：等级/期限/责任班组缺失的一次性补齐，
  每行打 `回填批次`，原值与推定依据写入审计（`urban-utility-tunnel:audit-log`，追加式）。
- **历史单据回填**（迁移 v2，以完工日期为轴，规则见 `src/data/history-editions.ts`）：
  渗漏水处置单与检修记录按完工年份选版本——`≤2020` 用 GB 51354-2019 初期台账口径、
  `2021–2023` 用运维细则细化口径、`≥2024` 用闭环留痕口径；只补残缺/占位值，真值不动，
  状态原口径保留；无完工日期回退发现日期/计划工期，都缺按最新版并标注"轴缺失"。
- **整改待办**（`/todo`）：不单独存储，由隐患表 1:1 投影，条数结构性恒等；处置结论在隐患行上，
  两边页脚都有对账结果。
- **班组权限**：写操作（派发/验收/退回/补录）限该隐患的责任班组（顶栏可切换班组演示）；
  非责任班组入口只读，提交按归属驳回且留痕。
- **对账**：隐患页"报表对账"展开可见四项校验（状态卡片合计=明细总数、待办=明细、
  逾期卡片=明细逾期标志、未结待办=未验收数），概览逾期卡同源。
- 迁移版本存在 `urban-utility-tunnel:schema-version`：v1 存量隐患回填、v2 历史单据补齐、
  v3 已验收隐患初排演练；迁移幂等，老版本 localStorage 打开即自动升级。
