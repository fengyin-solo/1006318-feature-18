# 隐患整改管理 · 一致口径方案

本文件说明隐患整改管理收口径的规则、取值依据与落库方式。代码实现集中在
`src/data/domain.ts`、`src/data/migration.ts`、`src/api/hazard-service.ts`，
列表（`views/hazard`）、整改待办（`views/hazard-todos`）、运营概览（`views/Dashboard`）、
应急演练（`views/emergency`）与各处导出**只读这一份推导结果**，不自行计数。

## 1. 单一事实源与原子落库

- 隐患主表（localStorage `hazard` 集合）是唯一底账；逾期、`pending`、`abnormal`、`整改状态`
  全部由 `normalizeHazard()` 在**读时**统一推导，不存在第二个口径。
- 验收动作在同一个事务里落库：隐患主表、整改待办、应急评估清单、重排演练计划
  通过 `savePatch()` 一次写入，任何入口读到的都是同一个版本，不会读到中间态。
- 退出再打开：数据持久化在 `localStorage`，启动时 `reconcileOnBoot()` 做幂等对账。

## 2. 验收、退回与幂等

- **验收通过**：隐患编号、隐患部位、隐患等级、整改期限与验收日期/验收班组/验收结论一次性落库；
  状态置「已验收」，`pending=false`，逾期标记（`abnormal`）随即清除；
  写一条流转留痕（时间、班组、操作人、说明）。
- **重复提交只生效一次**：已验收隐患再次提交直接拒绝（幂等键为隐患 id，验收次数仅在首次通过时 +1）。
- **退回重改**：必须填写退回原因；状态保持「整改中」，退回次数 +1，
  整改期限以 `max(今天, 原期限)` 为基准，按等级周期顺延，留痕记录期限的"前值 → 后值"。
- 逾期是**派生标记**，不是工作流状态：仅「待整改/整改中」且整改期限早于今天才算逾期，
  已验收永不逾期；因此没有手工"标记逾期"动作，逾期数随日期滚动、随验收清除。

## 3. 整改期限按等级推定（存量回填）

依据《安全生产事故隐患排查治理暂行规定》（原国家安监总局令第16号）"分级治理、限期整改"的原则，
结合管廊现场作业窗口，早年没有整改期限的隐患按发现日期起算推定：

| 等级 | 推定整改期限 |
| --- | --- |
| 重大 | 发现日期 + 7 天 |
| 较大 | 发现日期 + 15 天 |
| 一般 | 发现日期 + 30 天 |
| 低 | 发现日期 + 60 天 |

- 等级残缺统一登记为「一般」；责任班组残缺推定给默认责任班组「土建维保班」。
- 推定只补残缺值，原值一律保留；每处补齐写入「回填备注」（`存量回填v1`），导出可见。
- 回填幂等：已有回填标记的行不再处理。

## 4. 历史单据按完工日期为轴回填一次

适用于「渗漏水处置单」「设施检修记录」中的**已完工**历史单据（在办单据不拿历史模板套）：

1. 以**完工年份归版**：同年存在字段完整的已完工单据时，该单据即"当年那版"模板
   （同年多份时取字段最齐全的一份）；同年没有完整版时，取**年份最近**的完整版兜底。
2. 完工日期本身残缺的，按发现日期加该类单据典型工期推定（渗漏处置 14 天、设施检修 7 天），
   再用推定年份去定版。
3. 仅补残缺字段，补了什么、用的哪一版写进「回填备注」（`历史回填v1`）并记录回填日期；
   原值与历史记录原口径保留不动。该回填在首次打开新版时执行一次，之后不再变动。

## 5. 班组归属与只读入口

- 顶栏可切换责任班组：土建维保班、机电运维班、安消维保班、给排水班；
  另有「观摩账号（只读）」。
- 派发、验收、退回、补录均在服务层校验：非本责任班组的提交一律拒绝并提示归属班组；
  只读入口的任何写操作一律拒绝，页面相应按钮不展示。越权改动不会进入落库事务。

## 6. 跨模块同步

- **整改待办（另一个入口）**：一条未验收隐患对应一条待办，待办由隐患主表重建，
  验收通过即核销并回写处置结论，退回重改标题体现"退回重改"。
  对账等式恒成立：**未验收隐患数 ＝ 待核销待办数**（概览页、两个列表页都实时显示核对结果）。
- **应急演练评估清单**：每次验收（含通过与退回）同步一条评估结论；
  幂等键 `隐患id#验收序号`，重复提交不会产生第二条。早年已验收但无留痕的存量隐患，
  按验收字段补登一条。
- **重排演练**：每次验收后按最新未验收隐患自动生成一份「待组织」演练计划，
  上一份生效计划留痕为「已重排」；计划聚焦最高等级、最紧迫的隐患，建议日期为验收日后 14 天。

## 7. 补录规则

补录隐患时缺项一并由服务层补齐：编号按 `HAZA-年份-序号` 自动生成，
等级缺省「一般」，整改期限留空则按等级推定，责任班组取当前班组，
责任人员缺省取当前操作人，整改措施缺省"待责任班组细化整改措施"。
补录与存量回填互不影响：历史记录仍按原口径保留。

## 8. 报表与明细对账

- 隐患统计卡、状态图例、概览表异常量、导出清单、待办与评估清单全部来自同一套函数
  （`hazardSummary / hazardRows / listTodos / listAssessments`）。
- 隐患导出 CSV 附「是否逾期」列，行序行集与列表一致；评估清单、演练计划各自可导出。
- `scripts/verify-hazard.ts` 为端到端口径验证脚本（63 项断言覆盖上述全部规则）。

## 9. 验证方式

```bash
cd frontend
npm run typecheck
npm run build
# 端到端口径验证（用平台 linux arm64 的 esbuild 打包后在 Node 中运行）：
node_modules/@esbuild/linux-arm64/bin/esbuild scripts/verify-hazard.ts \
  --bundle --platform=node --format=esm \
  --outfile=/tmp/verify-hazard.mjs --alias:@=./src \
  && node /tmp/verify-hazard.mjs
```
